# 公寓宽带管理后台 Apple 风格重设计

## 目标

重建 `/guanli` 管理后台的前端骨架，解决当前管理后台源码与部署产物分离、路由不一致、页面交互不统一和视觉质量低的问题。保留现有 PostgreSQL 数据、Express API 与业务权限，先交付稳定的登录、全局导航和总览首页，再迁移业务模块。

## 当前问题

- 线上 `/guanli` 主要依赖独立静态构建产物，源码边界不清晰，导致修改难以追踪。
- 管理页面分散在 `app/admin`、`app/system`、`app/sales`、`app/maintenance` 等目录，缺少统一的管理后台入口和布局。
- `dist/guanli/assets` 存在多个重复的大体积 JavaScript/CSS 资源，增加加载失败和缓存不一致风险。
- 各页面的请求、加载、空状态、错误反馈和权限菜单缺少统一规范。
- `/guanli`、旧角色页面和 Vercel 静态导出规则之间存在耦合，容易出现 404 或旧页面缓存。

## 设计方向

### 视觉语言

采用“Apple Pro utility”方向：浅色界面、白色与雾灰背景、石墨黑正文、单一蓝色强调色、精细边框、低强度阴影、大留白和克制的进入动效。使用适合中文的系统字体栈并保留苹果设备的 SF 字体优先级；不使用紫色渐变、重玻璃拟态或无意义装饰。

### 信息架构

统一入口为：

```text
/guanli/login
/guanli/
/guanli/customers
/guanli/broadband
/guanli/tickets
/guanli/properties
/guanli/packages
/guanli/finance
/guanli/settings
```

旧入口 `/admin`、`/sales`、`/maintenance`、`/system` 保留兼容跳转，避免历史链接失效。

### 全局布局

- 桌面端：左侧窄导航栏、顶部上下文栏、中央内容工作区。
- 移动端：顶部标题和底部导航，内容区域适配安全区和触控尺寸。
- 导航根据角色显示可访问模块，未授权路径统一跳转到总览或登录页。
- 所有页面共用页面标题、面包屑、搜索栏、筛选栏、状态反馈、确认弹窗和 Toast。

## 第一阶段范围

### 登录页

- 简洁的品牌标题、登录表单和角色提示。
- 清晰的输入校验、提交中状态、登录失败提示和登录后跳转。
- 不在前端写死权限判断；登录结果统一写入会话并由路由守卫检查。

### 管理后台壳层

- 新建唯一的 `/guanli` Layout 与导航配置。
- 统一响应式断点、颜色变量、间距、圆角、阴影和动效。
- 统一 API 客户端，处理 JSON、超时、401、403、500 和网络错误。
- 统一页面加载骨架、空数据视图和错误重试操作。

### 总览首页

- “今日运营概况”作为首要区域。
- 指标：在线宽带、待处理工单、即将到期客户、今日收入。
- 展示最近工单、到期提醒和快捷操作。
- 图表只保留能支持决策的趋势，不引入复杂图表依赖。

## 第二阶段范围

按以下顺序迁移模块：

1. 客户管理
2. 宽带管理
3. 工单管理
4. 楼栋与房间
5. 套餐管理
6. 财务管理
7. 系统设置与数据导出

每个模块都必须使用统一的表格、筛选、分页、编辑抽屉、删除确认和错误处理组件。

## 技术方案

- 继续使用现有 Next.js 静态导出和 React 技术栈，避免引入第二套管理后台框架。
- 新增 `app/guanli` 作为唯一管理后台源码边界；模块页面按业务拆分。
- 新增管理后台共享组件目录，例如 `app/guanli/components`、`app/guanli/lib` 和 `app/guanli/types`。
- 保留 `backend/server.js` 和现有 `/api/*` 接口，先通过前端 API 客户端隔离接口细节。
- 逐步移除对旧 `dist/guanli` 独立构建产物的依赖；Vercel rewrite 改为指向新的静态导出路径。
- 不在本次设计中修改数据库表结构；涉及接口缺陷时增加兼容层或明确错误响应。

## 稳定性要求

- 页面首次加载不得因单个接口失败而白屏。
- 401 自动回登录页，403 显示无权限状态，500 提供重试按钮。
- 每个页面至少有空数据、加载中、接口失败和成功数据四种状态。
- 所有旧入口、`/guanli`、`/guanli/` 和主要静态资源路径都必须在构建后验证。
- 构建前后都检查 API 登录、总览数据和核心静态资源。

## 验收标准

- Vercel 公网首页和 `/guanli/` 均能打开，刷新后不出现 404。
- 管理员可以登录并进入总览，角色菜单不越权。
- 首页四项核心指标、最近工单和快捷操作可正常加载或显示明确失败状态。
- 桌面端与移动端均有完整导航，不出现横向溢出。
- 旧入口能兼容跳转。
- 构建退出码为 0，关键页面和 API 验证均通过。
- 代码不再依赖重复的独立管理后台 bundle。

## 非目标

- 本阶段不更换数据库、不重写 Express API、不新增在线支付。
- 不在没有业务需求的情况下加入复杂图表、AI 助手或额外第三方组件。
- 不删除现有业务数据和旧页面文件；迁移完成前保留可回滚路径。
